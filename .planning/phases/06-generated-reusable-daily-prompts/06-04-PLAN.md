# Phase 6 Slice 06-04 — Approved Library Selection and Ranking Plan

Date: 2026-08-01

## Goal

Add one deterministic, privacy-safe ranking boundary for lifecycle assignment from the approved reusable daily-prompt inventory. Use only aggregate completion counts and bounded reusable-prompt metadata, preserve recent-assignment avoidance and exact-fingerprint deduplication, and keep the six approved seeds as the automatic fallback.

## Protected baseline

- Preserve immutable lifecycle assignment, canonical prompt reads/writes, private-until-both-submit answers, and exact-once aggregate completion counting.
- Preserve Phase 5 planner, scheduler, reservation, dispatch, outcome, and notification behavior.
- Preserve Slice 06-03 generation validation/persistence and its lack of automatic provider invocation.
- Do not change schema, mobile routes, notification files, generation actions, cron wiring, credentials, live data, or provider configuration.

## Bounded ranking policy

1. Read at most 64 approved prompts through the existing `safetyStatus`, `completionCount`, and `createdAt` index.
2. Revalidate candidate documents and reject duplicate candidate IDs or normalized fingerprints.
3. Read at most 12 prior couple lifecycle assignments; use only prompt ID, category, and principle as bounded recency/diversity evidence. No answers, response rows, user identity, Moment, Chat, device, notification, or generated raw output enters the pure ranking boundary.
4. Exclude recently assigned prompt IDs whenever any fresh candidate exists. If all bounded candidates are recent, retain the inventory as the automatic fallback.
5. Among recency-eligible candidates, prefer the minimum exact-once aggregate `completionCount`.
6. Among equally completed candidates, prefer the lowest recent category-plus-principle frequency.
7. Resolve remaining ties deterministically by normalized fingerprint and the existing couple-day selection seed.
8. Recheck the selected fingerprint with the exact indexed lookup before freezing the assignment.

This policy deliberately does not add ratings, answer-derived quality, personalization, semantic similarity, embeddings, model scoring, editorial weights, or new persisted ranking state because the current schema does not safely support them.

## Test-first order

1. Capture RED with a missing pure ranking module and tests for completion evidence, recency, diversity, deterministic ties, all-recent fallback, bounds, malformed counts, and duplicate IDs/fingerprints.
2. Implement the pure, provider-free boundary and make its focused suite green.
3. Capture integration RED showing lifecycle assignment ignored aggregate completion rank.
4. Route only the existing approved bounded inventory and recent assignment metadata through the boundary, retaining the exact selected-fingerprint check.
5. Run focused selection/assignment/generation/prompt tests, full unit and Convex suites, typecheck, lint, formatting, whitespace, and repository validation/review gates.

## Non-goals and external effects

No schema or UI change; no model/provider invocation; no credential or configuration access; no cron or notification change/send; no migration, deployment, live data operation, install, external communication, commit, or push. Do not broaden into Phase 7 Quality Time.

## Argent applicability

Argent is not applicable. This slice changes only a pure backend ranking helper, lifecycle selection internals, backend tests, and planning records. It changes no route, rendered content, accessibility contract, interaction, or mobile runtime behavior; therefore there is no new UI route or screenshot to verify.
