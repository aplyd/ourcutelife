## Contract to implement

Use a closed Quality Time category type:

- `eat`
- `drink`
- `explore_adventure`
- `entertainment`
- `romance`

Export a deterministic legacy adapter only for the five current supported categories:

- `food -> eat`
- `drinks -> drink`
- `activity -> explore_adventure`
- `entertainment -> entertainment`
- `intimacy -> romance`

Unknown historical values such as `dinner`, `date`, and `weekend` must return no mapping rather than be guessed or rewritten.

Export pure decisions with structured result/disposition values (not throw-driven happy paths) for:

1. **Shortlist readiness**
   - Require at least one unique selected Quality Time category.
   - Reject unknown/duplicate categories, duplicate option IDs, options assigned to an unselected/wrong category, and malformed counts.
   - `ready` only when every selected category contains 3–5 unique initiator-accepted option IDs.
   - Distinguish incomplete from invalid so a later UI can disable Send without treating ordinary progress as corruption.

2. **Mutual reveal**
   - Inputs identify request status, viewer role, request category, whether the responder chose that category, initiator decision, responder decision, and whether an outcome already exists.
   - Return revealable only for the same request-scoped option when both decisions are `accept`, the responder selected the category, and the request is in an eligible sent/responding/completed state.
   - Draft, canceled, expired, exhausted/no-match, pass, missing/unknown, duplicate/ambiguous outcome, wrong-category, and one-sided acceptance must fail closed.
   - The result must never contain user IDs, creator/authorship, rejected IDs, ordering, timestamps, text, or partner decisions; this slice decides visibility only.

Names and exact internal types may be refined during implementation, but the observable rules above may not be weakened without updating canonical requirements/decisions first.

## Test-first matrix

Capture RED before creating the module, then GREEN with focused tests covering at minimum:

- each exact legacy category mapping and fail-closed unknown values;
- one selected category with 2 accepts is incomplete;
- 3 and 5 unique accepts are ready; 6 is invalid;
- multiple categories require 3–5 in every category;
- duplicate selected categories, duplicate option IDs, empty categories, wrong-category options, and unknown categories are invalid;
- draft state never reveals;
- initiator accept alone never reveals;
- responder accept without initiator accept never reveals;
- either pass never reveals;
- a responder-unselected category never reveals;
- canceled, expired, exhausted/no-match, malformed, and ambiguous outcome states never reveal;
- exact same-option mutual acceptance reveals once and only returns a visibility disposition;
- no returned object contains identity, authorship, private decision, or rejected-option fields.
